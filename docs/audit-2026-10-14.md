# dsh-hyperliquid 插件审计报告（2026-10-14）

> 审计范围：工作区源码（`index.js` + `lib/*` + `src/client/*`）、构建产物 `client.js`、
> 运行中的宿主实例（127.0.0.1:3080，经 cordis_inspect 实测）、测试与部署脚本。
> 结论前置：**代码质量整体扎实**（签名有官方向量对拍、风险限额 fail-closed、测试全绿），
> 但存在 1 个**正在生效的部署态问题**、一批架构/性能缺陷，以及若干与产品期望的偏差。

## 0. P0：正在生效的问题（先于一切代码修复）

### P0-1 运行中的宿主是旧代码，磁盘已是新代码 —— 新安全防线并未生效

**证据**
- GUI 宿主进程（PID 68040，`dsh web`，端口 3080）启动于 **10-13 17:32:42**；
- `lib/tools.js`（新版工具面）落盘于 **10-13 18:10:08**，晚于宿主启动 38 分钟；
- `client.js` 最近一次构建 **10-14 10:23:39**；
- 经 `cordis_inspect_query(Tool.listTools)` 实测：**当前运行宿主只有 4 个工具**
  （`hyper_market / hyper_account(无 orderStatus) / hyper_order(带 confirm 参数) / hyper_session`），
  而磁盘源码是 6 工具 + `hyper_decide` 一次性 decisionId 流。
- `~/.dsh/profiles/web/node_modules/dsh-hyperliquid` 是指向工作区的**符号链接**，
  所以"文件已更新"但"进程内模块图仍是旧的"。

**影响**
- 新构建的 client.js 票据文案指导 agent「先用 hyper_decide 获取一次性 decisionId，再用 hyper_order 执行」，
  但运行中的宿主**没有 hyper_decide 工具** → live 票据的指令在当前实例上必然走不通；
- 本次迭代的核心安全增量（服务端硬预检、30 秒一次性决策、orderStatus 对账、预算账本）
  在运行实例上**全部未生效**；本会话 agent 拿到的工具 schema 也是旧版。
- 一句话：**改了代码 ≠ 部署了代码。**

**修复**
1. 立即：重启 `dsh web` 宿主（或经 plugin_manager 重载插件），重开新会话验证
   `hyper_context / hyper_decide / orderStatus` 出现在工具面。
2. 流程：把「改 `lib/*.js` / `index.js` 必须重启宿主」写进 README 开发须知
   （`plugin_manager` 的"live profile 立即生效"仅指启停/配置，不含代码热载）。
3. 可选加固：`index.js` 启动时把自身文件内容的 hash 注入 `status()`；
   client.js 顶栏对比 status 的 buildHash 与自身 bundle hash，不一致时顶栏提示「宿主与前端版本不一致，请重启」。

### P0-2 遥测死角：状态永不刷新 + 全部失败静默（用户看到的是"体面的假象"）

**证据**
- `src/client/data.ts:19-25`：`loadStatus()` 只在 `startPolling()` 挂载时调用一次；
  失败置 `statusError` 后**永不重试、永不清除** —— 首帧失败则顶栏永远显示"远端不可用"；
  首帧成功、宿主后来挂掉，则顶栏继续显示旧的 network/mode/address/WS 徽章（撒谎）。
- `data.ts` 所有轮询 `catch { /* transient */ }` 静默；快照失败时界面**冻结在旧数据上无任何提示**，
  没有"最后更新时间"，没有 stale 遮罩。

**修复**
1. `status` 纳入慢轮询（10s 一档即可），statusError 可恢复。
2. 全局 stale 指示：快照/账户连续 N 次失败（或 observedAt 超过 5s）时，顶栏出现
   「数据已暂停更新」横幅 + 主题置灰；恢复后自动消除。
3. 每个面板角落显示 `observedAt` 相对时间（`relTime` 已有现成实现）。

## 1. 架构问题

### A-1 「桌面焦点」存在两条不一致的同步路径（双真相源）
- 路径 1：`sessions-column.tsx:24-31` 点击会话 → `bindCoin` RPC（宿主 `desk.coin` + 事件，正确）。
- 路径 2：`chat-column.tsx:59-64` 挂载会话时按 registry `row.coin` **仅本地 patch** `activeCoin`，
  既不 `pushDeskCoin` 也不立即 `loadSnapshot` —— 宿主 system-prompt 里的"当前交易台焦点"可能与 UI 实际显示脱节
  （bindCoin 被 `.catch(() => {})` 吞掉时必然脱节）。
- **修复**：客户端任何 `activeCoin` 变更统一收敛到一个 `setDeskCoin()`（本地 patch + `deskState` RPC + 立即拉快照/K线），
  删除 chat-column 的旁路跟随；事件回流只作为 agent→UI 方向。

### A-2 浏览器可直呼下单 Remote 方法，削弱"所有下单都通过会话"的核心不变量
- `lib/remote.js:721-726` 把 `placeOrder / cancelOrder / setLeverage / orders` 都标记为浏览器可调 Remote；
  `test/markers.test.mjs` 自己也承认它们是"仅宿主/工具侧使用"。但新 UI 已完全不用它们（grep 证实）。
- 后果：paper 模式下，任何能碰到本机 RPC 的调用方可以**绕过会话与事件链**直接 `hyper/placeOrder`；
  live 模式下 UI 若误用会得到费解的 `live 签名仅允许从 DSH agent 工具调用`。
- **修复**：从浏览器 marker 列表移除 `placeOrder/cancelOrder/setLeverage/orders`
  （工具侧走 `executeToolOrder/executeToolCancel/executeToolLeverage`，UI 侧走票据→会话，两条腿都完整）；
  或至少给 paper 路径也加 `requireTradingSession`。markers 测试同步收紧。

### A-3 事件契约是两处手写的魔法字符串（已有一处真实断裂）
- 宿主 `lib/store.js:170` 发的是 `live.order.` + status（`live.order.accepted` 等）；
  客户端 `data.ts:89` 只精确匹配 `'live.order'` → **永不相等**，live 下单后的事件驱动刷新是死代码
  （目前靠 3s 轮询兜底掩盖）。
- **修复**：共享一份事件 kind 常量（或客户端 `startsWith('live.order')`）；在 `test/markers.test.mjs`
  旁边加一条静态契约测试：扫描 `src/client/data.ts` 里的事件 kind 字面量 ⊆ 宿主 `recordEvent` 调用集合。

### A-4 宿主锚定是隐式契约，失败信息不指向根因
- `lib/remote.js:21-65` `resolveTypertRuntime` 靠 `argv[1]/argv[0]` 锚定 + `require(esm)`（Node ≥ 22.12 才可用）；
  `index.js:20-35` schemastery 同样双份解析。失败时只报"无法解析"，不提示 Node 版本或锚定机制。
- **修复**：收敛到 `lib/host-runtime.js` 单点；报错附带「需要 Node ≥ 22.12（require(esm)）与 dsh 宿主进程锚定」说明；
  README 记录 engines 下限。

## 2. 性能问题

### P-1 `markets()` 每周期多发一倍 REST
`lib/remote.js:235`：`Promise.all([meta(), metaAndAssetCtxs()])` —— `metaAndAssetCtxs` 的返回值
**本身就包含 meta**。每 15s 白打一次 REST（≈240 次/小时/桌）。
**修复**：只调 `metaAndAssetCtxs`，从 `res[0]` 取 universe。

### P-2 paper 账户轮询绕过 WS 快照直打 REST
`lib/remote.js:711-718` `safeMids` → `client.allMids()`（REST）；`account()` paper 路径每 3s 调一次
（默认 paper 模式 = 20 REST/分钟），而此时 allMids 的 WS 快照几乎总是热的（snapshot 每 0.9s `touch(allMids)`）。
这与 README 宣称的「浏览器轮询宿主而非交易所」的架构承诺相悖。
**修复**：`safeMids` 先读 `client.snapshot(keys.allMids())`，未命中再 REST 兜底。

### P-3 K 线图表每次换币/换周期销毁重建 3 次
`src/client/components/desk-column.tsx:87`：`key={coin + ':' + interval + ':' + candlesState}` ——
`candlesState` 走 `ready→loading→ready`，key 变两次 = lightweight-charts 实例**卸载再建两次**（闪烁 + 浪费）。
**修复**：key 只留 `coin + interval`；loading 用覆盖层表达。

### P-4 K 线最后一根蜡烛永不更新（性能与期望双重问题）
K 线只在换币/换周期时 REST 拉一次；交易台的图表是**冻结的**，而盘口/成交每 0.9s 在跳。
`lib/hl.js` 已实现 candle WS 通道（`_openChannel` case 'candle'）但从未被 remote 触碰 —— M2 死代码。
**修复（分级）**：
- a（一天内可做）：客户端用 0.9s 快照的 mid 对最后一根 candle 做 `series.update()`；
- b（正式）：`snapshot()` 同时 `touch(keys.candle(coin, interval))`，把 WS 最新 candle 随快照下发；
- 顺带：`trades` 无 REST 回退，冷启动前几秒成交面板空白 —— 可复用 `recentTrades()` 补首帧。

### P-5 `_retryChannel` 单定时器吞掉其他 key 的重试
`lib/hl.js:261-282`：`if (this.reconnectTimer) return` —— key A 失败挂起 3s 定时器期间 key B 失败，
B 的重试被吞；此后 `touch()` 因 `subs.has(key)` 为真不再触发 subscribe → **B 永久退化为 REST 回退**，
且被 `snapshot()` 的 REST 兜底静默掩盖。
**修复**：retryTimer 改 `Map<key, timer>`；或重试回调里扫描所有 `listeners>0 && !channel` 的 row 一并重开。

### P-6 渲染与轮询卫生（低优先级）
- store 每 0.9s 收到新 snapshot 对象 → 全部订阅者重渲染；`BottomTable`/`BookCard` 可 `React.memo`，
  snapshot patch 可按 seq 去重。
- 轮询不感知 `document.hidden`（后台标签仍 1Hz 打宿主）；面板隐藏时如 shell 未卸载组件则持续空转 ——
  加 `visibilitychange` 暂停/恢复是廉价优化。
- `candles()` 无缓存：来回切币重复全量拉取；加 per `coin:interval` 10s TTL 缓存。

## 3. 是否符合用户期望（产品/UX）

### U-1 币种选择器只有前 100 个合约、无搜索
`desk-column.tsx:23` `s.markets.slice(0, 100)`（universe 原始顺序，非热度排序），且无搜索框；
agent 侧 overview 也只有 top20。HL 有 200+ 永续，**用户在 UI 上选不到大部分币**。
**修复**：markets 本就全量返回，做一个可搜索 combobox（输入过滤 + 常用币置顶）即可，无需改宿主。

### U-2 paper 与 live 的规则在 UI/宿主两处不一致
- 票据杠杆选择器被 **live 配置**的 `maxLeverage`（默认 2）钳制（`trade-ticket.tsx:27`），
  但 agent 在 paper 可设 1-50 —— 同一桌面上 UI 与 agent 能力对不上；
- paper 市价滑点 0.05%（`remote.js:520`）vs live 5% 保护带（`remote.js:549`）—— paper 成交价过于乐观；
- paper 无保证金占用/强平模拟，杠杆亏穿后权益可为负仍可继续交易（README 已声明简化，但 UI 无任何提示）；
- paper 限价单只支持立即成交方向（`remote.js:517`），票据不做预检，用户提交后才由 agent 报错。
**修复**：paper 杠杆上限用 `market.maxLeverage`；票据校验复刻宿主 paper 规则（限价可成交性）；
paper 模式在顶栏/票据给出「简化撮合：固定滑点、无强平」说明；account 面板显示保证金占用。

### U-3 会话列表只增不减
`removeSession` 仅在用户删除 dsh 会话后的自动清理路径触发；桌面 UI **没有任何删除/归档入口**，
长期使用后左栏堆积废弃交易会话。
**修复**：会话行加删除按钮（调 `removeSession` + 可选提示是否同时关闭 dsh 会话）。

### U-4 i18n 半途而废
`locale.ts` 有完整 zh/en 字典，但 `desk-column`（标记价格/预言机/24h 涨跌/K 线/资金费历史）、
`trade-ticket`（保证金模式/杠杆/限价/数量/全部校验文案）、`divider`（收起会话栏）、
funding 面板、inline 错误等**大量字符串硬编码中文**；`locale/*.json` 只有 meta 两行。
en 用户看到混合语言。
**修复**：二选一并执行——(a) 硬编码全部过 `t()`；(b) 明确只支持 zh，删除 en 字典避免误导。

### U-5 票据止盈/止损的阻塞体验
勾选 TP/SL 立即 `errors.push` 硬阻塞（安全优先，正确），但错误位次靠前时用户先看到阻塞而非引导。
**修复**：TP/SL 的提示单独成块给出替代路径（「先下主单，再让 agent 用 hyper_order 分步补保护单」），
不与其他校验错误竞争 `errors[0]`。

## 5. 测试盲区（配合上面修复补齐）

- `hl.js` subscribe/unsubscribe/retry 状态机**零测试**（P-5 这类 bug 正是从这里漏掉的）；
