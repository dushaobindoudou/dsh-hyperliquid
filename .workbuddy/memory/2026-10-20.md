### 决定性发现
- ETH 会话 `8f569b1b`（10-19 17:26 被用户归档）在 15:30 / 15:45 / 16:00 各收到一次
  `[交易台市场检查]`，turn 全部在 22–1140ms 内 `blocked`，**无 step/start、无 request/header**
  （零模型请求），消息还被 `agent/inbox/spliced {removedCount:1}` 删除 → 完全静默失效。
- 对照：BTC 会话 `8e50a65c` 同一时刻 16:00:09 → 16:02:54 `completed`，正常执行。
- 根因链条：
  1. `lib/strategy-monitor.js:31-34` 用 `sessions.find(row => row.coin === coin)` +
     `listSessions()` 按 `createdAt` 倒序 → 只叫醒「该币最新创建的会话」，不检查是否归档/可执行。
  2. `index.js:119-128` `deliver()` 只 `followup` 入队就 `return true`，从不观察 `turn/end`；
     `wake.js:40` 收到 true 就记 `lastAt` 进冷却 → 失败永不重试、无日志。
  3. bar 分辨率 15m，`FRESH_MS=2min` 错过即丢且不补发；主网被 `network !== 'testnet'` 挡掉，
     且触发单（normalTpsl）只在测试网 → 主网零自动保护。
  4. 风控（日亏 2R / 连亏减半）只在 `lib/prompt.js` 提示词里，硬闸只有交易限额。
  5. `turn-origin.js:36` 的 `&& !turns.get(session)?.automatic` 让人工插话无法解除 automatic 标记。
- 数据面：10-20 一天 3 连亏（-1.07R / -0.62R / -1.77R），权益 99.9 → 93.15；
  14:14 缠论会话撤销了 `9b6aed6b` 的 3 张挂单（两策略抢同一 BTC 账户的实证）。
  当前 testnet 持仓 BTC 0.002 @81120，SL 80704 / TP 82263 reduceOnly 在位。
